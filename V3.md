# SAFIM v3 on the fixed benchmark harness

`fix-bench-dataset` starts from `fix-bench` commit
`f94716071974f89165d3319d24a364130aa83947` and adds v3 support. The original
`fix-bench` and `dataset` branches are unchanged.

## Setup

This branch includes the `safim_v3` loader, Docker worker, versioned checkers,
metadata helpers and runtime registry. Clone this branch and run from its root
in a dedicated Python 3.12 environment:

```sh
python -m pip install -r requirements-v3.txt
```

No parent repository or editable installation is required. See
[standalone setup](V3_STANDALONE.md) for cloning, bundle provenance and an isolated
smoke check. Record the full environment, hardware and model revision for each
experiment. The bundled evaluator is a byte-preserving copy of the recorded
parent revision, shared identically with the `dataset` branch.

## Dataset and execution

Both `block_v3` and `control_v3` default to `averoo/safim_v3`, revision
`70edeef93658085e8ab905e5688996d098b8172e`, split `test`. They contain 802 and
1,124 items respectively, in C++, Java and Python. The loader restores metadata,
checks test-payload hashes, and retains runtime, limits, custom checker versions,
and comparison rules. Legacy configuration defaults and their pinned original
dataset revision are unchanged.

`--dataset-source` accepts a Hub repository, a local exported snapshot directory,
or metadata-bearing JSONL. `--dataset-revision` selects a different revision;
mutable revisions are resolved once before downloading files. Optional
`--dataset-filters filters.json` uses the bundled metadata filters.
Use the same source, revision and filters for generation, evaluation and reporting.
Run metadata records hashes of input files, filter values and ordered selected IDs;
changed recorded inputs are rejected during evaluation.

V3 execution uses the same bundled `safim_v3.runner.DockerRunner` as the `dataset` branch.
Supply `--runtimes configs/runtimes.v3.json`, or an
equivalent registry of available Docker images pinned by digest. Image availability
is a prerequisite; the registry does not download or rebuild the environment.
The public dataset also carries `metadata/runtimes.json`. ExecEval's `--exec-profile`
does not apply to v3 and cannot be combined with its Docker registry.

## Commands

Run from the clone root. Replace `MODEL` with a model identifier supported
by the chosen branch. Use separate caches and output files for the two branches.

```sh
python generate.py MODEL block_v3 cache-fixed-block.json predictions-fixed-block.jsonl infilling --dataset-source averoo/safim_v3 --dataset-revision 70edeef93658085e8ab905e5688996d098b8172e --post_processors truncate_line_until_block
python evaluate.py block_v3 predictions-fixed-block.jsonl results-fixed-block.jsonl --dataset-source averoo/safim_v3 --dataset-revision 70edeef93658085e8ab905e5688996d098b8172e --runtimes configs/runtimes.v3.json
python show_detailed_results.py block_v3 results-fixed-block.jsonl --format json
```

For control completion, use `control_v3`, separate filenames and the
`truncate_control` postprocessor. Set and record model, seed, token budget and
context options explicitly as appropriate for each branch's model adapter.

Exact reference strings pass automatically by default on both branches. On
`fix-bench-dataset`, `--force-execution` disables that shortcut; per-row and run
metadata distinguish reference matches from execution. Keep this policy aligned
between experiments. Infrastructure errors stop a fixed-harness run as incomplete,
with `passed: null`; they are not silently scored as model failures. Missing
predictions are rejected unless `--allow-partial` explicitly requests a subset.

## Expected differences from `dataset`

The fixed model wrappers, context budgeting, generation persistence, parser,
postprocessors, result validation and reporting remain those of `fix-bench`.
V3 block prompts use its existing block templates. V3 control prompts use its
`control_fixed` templates and postprocessing because the header colon stays in
the Python context, outside the answer. The `dataset` branch keeps its original
control templates; this intentional difference belongs to the framework comparison.

The port does not change `model_utils.py`, `ast_utils.py`, existing demonstration
text, dataset rows or worker/checker code. It does not establish equivalent
model outputs across the two branches. Compare the same dataset revision and item
set, runtime registry, prompt mode, model/tokenizer revision, output budget, seed
policy and scoring policy, and report the framework differences explicitly.

Regression suite (from the clone root):

```sh
python -m unittest discover -s tests -q
python -I tests/standalone_v3_smoke.py --docker
```

The second command verifies bundled file hashes and import isolation, exercises
both configs using small local fixtures, and executes non-exact Python completions
through the actual Docker dispatch. It is a smoke test, not a model benchmark.
